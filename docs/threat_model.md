# Marketing Campaign Agent: Threat Model

## 1. System Assets

| Asset ID | Asset Name | Description | Sensitivity |
| :--- | :--- | :--- | :--- |
| **A1** | Customer Database (`customers.db`) | Synthetic customer records with demographic and behavioral metrics. | Integrity / Availability |
| **A2** | API Credentials | Google Gemini API key (`GEMINI_API_KEY`) and optional LangSmith key. | Confidentiality |
| **A3** | Marketing Copy & Angles | Generated advertising deliverables across search, social, and email channels. | Integrity / Quality |
| **A4** | Run State & Audit Logs | Historical execution records (`runs.db`), rate events, and SQL audits. | Integrity / Auditability |
| **A5** | Compute & Cost Budgets | Tool call ceiling (15 calls) and monetary budget ($0.25 ceiling). | Financial / Resource |

## 2. Trust Boundaries

```
[Untrusted: User Web Input / Brief]  ---> [Boundary 1: Sanitizer & Pydantic Validator]
[Untrusted: Web Search Snippets]     ---> [Boundary 2: Untrusted Markup & LLM Context]
[LLM Tool Request: SQL String]       ---> [Boundary 3: sqlsafe Validator & Read-Only SQLite Engine]
[UI Payload: Approval Action]        ---> [Boundary 4: Store State Machine (Angle by Index)]
[System Telemetry: Logs & Traces]    ---> [Boundary 5: Structlog Filter & Redactor]
```

1. **Boundary 1 (Input Entrypoint)**: Product briefs provided by staff. Staff accounts may be compromised or enter adversarial prompt injection payloads.
2. **Boundary 2 (Web & External Data)**: Search engine results or external third-party pages may contain indirect prompt injection attacks designed to hijack model instructions.
3. **Boundary 3 (Database Querying)**: SQL queries generated by LLM tool calls. The model cannot be trusted to produce safe, non-destructive SQL.
4. **Boundary 4 (Human Approval Gate)**: Web dashboard actions approving or rejecting campaigns. Client payloads may attempt to manipulate approved angle copy.
5. **Boundary 5 (Observability & Logging)**: Diagnostic logs must never expose secret keys, personal identifiers, or full unescaped injection strings.

## 3. Threat Analysis & Security Controls (S1 – S11)

| Threat ID | Threat Description | Attack Vector | Security Control (SPEC ID) | Verification Test |
| :--- | :--- | :--- | :--- | :--- |
| **T-01** | Database destruction or tampering via SQL injection | Model emits `DROP TABLE`, `INSERT`, `ATTACH`, or destructive comments (`--`, `/*`). | **S1, S2**: Strict 7-rule validator (`sqlsafe.py`) and 3-layer read-only connection (`mode=ro`, `query_only`, bytecode authorizer). | `tests/test_sqlsafe.py` (44 hostile cases), `tests/test_db.py` |
| **T-02** | Bypassing SQL validation | Obfuscated queries, stacked statements, or recursive CTE denial-of-service. | **S2**: Read-only SQLite connection rejects writes even if validator is bypassed; authorizer rejects recursive CTEs; progress handler halts runaway execution. | `test_db_authorizer_rejects_modifications`, `test_db_step_limit_aborts_runaway_query` |
| **T-03** | Silent SQL exploitation / lack of audit trail | Attacker attempts unauthorized database inspection without logging. | **S3**: Fail-closed audit logging (`audit/sql_audit.jsonl`). Any I/O audit failure immediately aborts query execution. | `tests/test_sql_audit.py` |
| **T-04** | Tool argument fuzzing and buffer overflow | Unexpected arguments or invalid types sent to internal tools. | **S4**: Strict Pydantic models with `extra="forbid"`, bounded ranges, and exception wrapping returning JSON error strings. | `tests/test_tools.py`, `tests/test_models.py` |
| **T-05** | Direct prompt injection via product brief | Staff brief contains instructions to leak data or override prompts. | **S5**: Input sanitization strips control chars; keyword injection scanner fails closed with `HostileInputError`. | `tests/test_sanitize.py` |
| **T-06** | Indirect prompt injection via web search results | Competitor search snippet contains hidden system override commands. | **S6**: Search snippets wrapped in `<untrusted>` tags, stripped of control characters, and treated as passive data. | `tests/test_scripted.py::test_scripted_model_injection_in_fixtures_does_not_alter_angles` |
| **T-07** | Runaway tool loops & resource exhaustion | Rogue model makes 100+ tool calls or burns through token budget. | **S7**: Unified middleware bound: exactly 15 tool calls and $0.25 notional cost ceiling across both phases. | `tests/test_cost.py`, `tests/test_agent.py` |
| **T-08** | Denial-of-Service via request flooding | Single user submits continuous campaign requests. | **S8**: SQLite sliding-window rate limiter enforcing 5 runs per hour per user. | `tests/test_ratelimit.py`, `tests/test_store.py` |
| **T-09** | Secret credential leakage into logs | API keys or raw customer database rows leaked into log files or telemetry. | **S9**: `SecretStr` wrappers for all keys; structlog filter drops sensitive keys; unit test greps captured logs. | `tests/test_logging.py`, `tests/test_config.py` |
| **T-10** | Approval gate parameter tampering | Attacker modifies UI payload to draft unapproved or malicious angles. | **S10**: Phase 2 retrieves angle strictly by index from `runs.db`, ignoring angle copy from the UI. | `tests/test_service.py` |
| **T-11** | Unintended tool side effects | Tool implementations attempt to write files or trigger unauthorized external web calls. | **S11**: Abstract Syntax Tree (AST) boundary test asserts zero file write or external execution calls in `src/campaign/tools/`. | `tests/test_boundaries.py` |

## 4. Residual Risks

1. **Model Hallucination of Evidence**: While evidence strings must be provided in `CampaignAngle`, LLM models can theoretically hallucinate evidence not present in tool results. Mitigated by `explain_run.py` joining angles with trace lines.
2. **Timing Attacks on Rate Limiter**: Sub-millisecond concurrent requests from the same user could theoretically race SQLite writes. Mitigated by transaction locks on `rate_events`.
3. **Indirect Prompt Injection in Paid Gemini Mode**: Advanced zero-shot indirect prompt injection techniques may subtly influence copy tone. Mitigated by word-boundary compliance filtering (`src/campaign/compliance.py`) and plain text dashboard rendering.
